# คู่มือนักพัฒนาและ AI สำหรับ BDC POS

เอกสารนี้เอาไว้ให้คนหรือ AI อ่านก่อนแก้ระบบ

## เป้าหมายระบบ

BDC POS เป็นเว็บแอพแบบ static HTML/CSS/JavaScript เชื่อม Firebase Realtime Database ใช้กับร้านอาหาร/เครื่องดื่ม มีระบบรับออเดอร์ ครัว แคชเชียร์ รายงานยอดขาย และหลังบ้าน

## ไฟล์หลัก

- `index.html` โครงหน้าและ modal ทั้งหมด
- `หน้าตาแอพ/หน้าตาแอพทั้งหมด.css` สี layout responsive mobile/iPad
- `โค้ดระบบ/01_ตั้งค่าและตัวช่วยกลาง.js` Firebase URL, state, helper, initial data
- `โค้ดระบบ/02_หลังบ้านจัดการร้าน.js` admin, menu, topping, staff, table, cleanup, audit log
- `โค้ดระบบ/03_รับออเดอร์และตะกร้า.js` menu grid, option modal, cart add
- `โค้ดระบบ/04_ล็อกอินและสิทธิ์.js` login, permissions, navigation
- `โค้ดระบบ/05_โต๊ะครัวสถานะแคชเชียร์.js` table map, submit order, kitchen/status/cashier/payment
- `โค้ดระบบ/06_รายงานยอดขายและส่งออกไฟล์.js` sales report, export CSV, app startup

## Firebase paths

- `Staff` พนักงานและสิทธิ์
- `Menu` เมนูอาหาร/เครื่องดื่ม
- `Options` เซ็ตตัวเลือก/ท็อปปิ้ง
- `Tables` ผังโต๊ะ
- `Orders` บิลและออเดอร์
- `AuditLogs` ประวัติการทำงาน

## ถ้าจะเพิ่มระบบใหม่

### ระบบตัดสต๊อค

แก้/เพิ่มหลัก ๆ ที่:

- เพิ่ม path ใหม่ใน Firebase เช่น `Inventory`, `StockMovements`, `Recipes`
- เพิ่ม UI หลังบ้านใน `index.html` หน้า admin
- เพิ่ม logic ในไฟล์ใหม่ หรือแยกจาก `02_หลังบ้านจัดการร้าน.js`
- จุดที่ต้องผูกกับยอดขายคือ `submitOrderToKitchen()` และ `confirmPayment()` ใน `05_โต๊ะครัวสถานะแคชเชียร์.js`

### ระบบเช็คอินพนักงาน

- ใช้ `Staff` เดิม หรือเพิ่ม `Attendance`
- ปุ่มเข้า/ออกงานควรอยู่หลัง login
- logic อยู่ใกล้ `04_ล็อกอินและสิทธิ์.js`

### ระบบสมาชิก

- เพิ่ม Firebase path เช่น `Customers`, `MemberPoints`
- หน้าเลือก/ค้นหาลูกค้าอยู่ฝั่งรับออเดอร์ใน `03_รับออเดอร์และตะกร้า.js`
- การสะสมแต้มควรผูกตอน `confirmPayment()`

## จุดเสี่ยง performance

ตอนนี้บางหน้าดึง `Orders.json` ทั้งก้อน เช่น active order และรายงานยอดขาย ถ้าข้อมูลโตมากควร refactor เป็น:

- `ActiveOrders` สำหรับบิลที่ยังเปิดอยู่
- `OrderHistory/YYYY-MM-DD` สำหรับบิลที่จบแล้ว
- `DailySummary/YYYY-MM-DD` สำหรับรายงานยอดขายเร็ว ๆ

ร้านยอดขาย 50,000 บาทต่อวันน่าจะใช้ได้ช่วงแรกถ้าจำนวนบิลไม่โหดมาก แต่ถ้าต้องรองรับ 200,000-1,000,000 บาทต่อวันแบบมั่นใจ ให้ทำ ActiveOrders/History/DailySummary ก่อนใช้งานหนัก

## ระบบส่วนลดท้ายบิลและใบเสร็จ

จุดที่เกี่ยวข้อง:

- `index.html` มี checkbox สิทธิ์ `permDiscount` ในหน้าจัดการพนักงาน และ modal `qrModal` สำหรับส่วนลดตอนชำระเงิน
- `โค้ดระบบ/02_หลังบ้านจัดการร้าน.js` บันทึกสิทธิ์พนักงาน `Permissions.discount`
- `โค้ดระบบ/04_ล็อกอินและสิทธิ์.js` ให้ `Admin Test` มีสิทธิ์ discount
- `โค้ดระบบ/05_โต๊ะครัวสถานะแคชเชียร์.js` มี logic หลักของ `canApproveDiscount()`, `calculateDiscountPreview()`, `confirmPayment()`, `printReceipt()`
- `โค้ดระบบ/06_รายงานยอดขายและส่งออกไฟล์.js` แสดงส่วนลดในประวัติบิล และเรียก `printPaidReceipt()` เพื่อออกใบเสร็จซ้ำ

โครงสร้างข้อมูลบิลที่จ่ายแล้ว:

- `subtotalAmount` ยอดก่อนส่วนลด
- `discount` เป็น `null` ถ้าไม่มีส่วนลด หรือ object ที่มี `type`, `value`, `amount`, `reason`, `approvedBy`, `approvedAt`
- `totalAmount` ยอดสุทธิหลังส่วนลด
- `paidAt` เวลาที่รับชำระเงิน
- `cashierName` คนที่รับชำระเงิน

กฎสำคัญ:

- คนที่มี `cashier` อาจรับเงินได้ แต่ใส่ส่วนลดไม่ได้
- คนที่มี `discount` หรือ `admin` เท่านั้นที่ใส่ส่วนลดได้
- ถ้าใส่ส่วนลด ต้องมีเหตุผล เพื่อเก็บไว้ตรวจย้อนหลัง

ข้อควรระวัง:

- `index.html` มี modal `adminMenuImportModal`

## ระบบอาหารชุด (Combo Set) และการอัปเกรด UX/UI [อัปเดต V9.9.5+]

ระบบได้รับการอัปเกรดครั้งใหญ่เพื่อรองรับการทำงานกับเซ็ตอาหาร และการแสดงผลที่ตอบโจทย์อุปกรณ์เคลื่อนที่อย่างเหมาะสม โดยมีข้อมูลทางเทคนิคที่ควรทราบดังนี้:

### 1. ระบบจัดการอาหารชุด (Combo Set System)
*   **โครงสร้างของขั้นตอน (Step Structure):** ในตาราง `Menu` หากฟิลด์ `IsCombo` เป็น `true` ข้อมูลขั้นตอนจะถูกเก็บในอาร์เรย์ `ComboSteps` ซึ่งแต่ละขั้นตอนประกอบด้วย:
    *   `id`: รหัสขั้นตอน (timestamp)
    *   `title`: ชื่อขั้นตอน (เช่น เลือกเครื่องแกง)
    *   `required`: บังคับเลือก (`true` / `false`)
    *   `type`: รูปแบบการเลือก:
        *   `fixed_all`: ได้รับทุกเมนูในขั้นตอนนี้โดยอัตโนมัติ (หน้าร้านจะล็อกสถานะและแสดงสัญลักษณ์ `🔒 บังคับในเซ็ต`)
        *   `pick_one`: เลือกได้เพียง 1 เมนู (หน้าร้านใช้โครงสร้าง Radio)
        *   `pick_many`: เลือกได้หลายเมนู (หน้าร้านใช้โครงสร้าง Checkbox)
    *   `limit`: จำนวนรายการสูงสุดที่เลือกได้ (ใช้สำหรับขั้นตอนประเภท `pick_many`)
    *   `items`: อาร์เรย์รายการอาหารในขั้นตอนนี้ แต่ละตัวประกอบด้วย `menuKey`, `extraPrice` (ราคาส่วนต่าง), และ `variant` (ล็อกรูปแบบขนาดเจาะจงล่วงหน้า)
*   **การล็อกรูปแบบสินค้าล่วงหน้า (Variant Restrictions):** แอดมินสามารถเลือกล็อกรูปแบบของเมนูย่อยไว้ล่วงหน้าจากหลังบ้าน (เช่น ล็อกเฉพาะขนาด "ชุดเล็ก" ของเมนูข้าวตัง) ข้อมูลจะบันทึกในฟิลด์ `variant` ของไอเท็มนั้น และหน้าร้านจะตรวจจับเพื่อล็อกไม่ให้พนักงานเปลี่ยนขนาดได้อัตโนมัติ
*   **การประกอบและแสดงผล:** ออเดอร์ที่สั่งจะถูกรวมชื่อเข้าตะกร้าในรูปแบบ `ชื่อเมนูหลัก [เมนูย่อย 1 (ตัวเลือกเสริม), เมนูย่อย 2]` 
    *   ระบบประมวลผลการแสดงผลบนบิล ครัว และใบเสร็จด้วยฟังก์ชัน `formatItemNameHTML()` ใน `05_โต๊ะครัวสถานะแคชเชียร์.js` โดยแยกรายการย่อยออกคนละบรรทัด คั่นด้วยสัญลักษณ์ลูกศรชี้ `↳` เพื่อการสื่อสารที่ถูกต้องแม่นยำ

### 2. การควบคุมการใช้สัญลักษณ์เครื่องหมายพิเศษ
*   **เครื่องหมาย `/` (Slash):** ใช้ในการแยกหมวดหมู่หลักและหมวดหมู่ย่อยในคอลัมน์ `หมวดหมู่` ตอนนำเข้า Excel (เช่น `Beverage/Coffee` -> หมวดหลัก `Beverage`, หมวดหมู่ย่อย `Coffee`) หน้าร้านจะแยก dropdown และกรองตามสแลชนี้
*   **เครื่องหมาย `|` (Pipe) และ `:` (Colon):** 
    *   ใช้สำหรับช่อง **รูปแบบ (Variants)**: `ชื่อรูปแบบ1:ราคา1 | ชื่อรูปแบบ2:ราคา2` (คั่นราคาด้วย `:` คั่นตัวเลือกด้วย `|`)
    *   ใช้สำหรับช่อง **ท็อปปิ้ง (Option Sets)**: `ชื่อกลุ่ม1 | ชื่อกลุ่ม2` (คั่นกลุ่มตัวเลือกเสริมด้วย `|`)

### 3. การแสดงผลจอครัวและการจัดหน้าจออุปกรณ์เคลื่อนที่ (Responsive UI/UX)
*   **จอครัว (Kitchen Monitor):** ได้รับการปรับแต่งให้อ่านง่ายจากระยะไกล ขยายขนาดฟอนต์ชื่ออาหาร ปริมาณ และตัวเลือกย่อยให้หนาและชัดเจนขึ้น พร้อมแปลงสีของหมายเหตุพิเศษ (📌) ให้แสดงผลในกรอบสีแดงสะดุดตา เพื่อความปลอดภัยในการปรุงอาหาร
*   ** drawer ป๊อปอัปหน้าร้าน:** ป๊อปอัปแบบเลื่อนจากด้านล่าง (Drawers) ทั้งหมดในหน้าร้าน จะทำงานแบบเต็มขอบจอเฉพาะบนมือถือ ส่วนบนแท็บเล็ตแนวตั้ง (iPad Portrait) หรือหน้าจอที่กว้างกว่า `sm` (>= 640px) ตัวป๊อปอัปจะจำกัดความกว้าง (`sm:max-w-xl` หรือ `sm:max-w-2xl`) และจัดกึ่งกลางอัตโนมัติ ทำให้หน้าเว็บดูหรูหราพรีเมียมและไม่ล้นเป๋ออกด้านข้างครับ
*   **กล่องระบุหมายเหตุทันที:** ทุกเมนูเดี่ยวที่ถูกคลิกสั่ง ระบบจะเปิดป๊อปอัป Option modal ขึ้นมาเสมอเพื่อให้พนักงานกรอกข้อความพิเศษได้ทันที ไม่เกิดการลืมใส่รายละเอียดยิบย่อย
*   **ป๊อปอัปเลือกโต๊ะด่วน (`#tablePromptModal`):** ระบบจะทำงานแจ้งเตือนเด้งให้ระบุประเภทการบริการและโต๊ะปลายทางทันทีที่พนักงานกดส่งออเดอร์โดยไม่ได้ใส่เลขโต๊ะ ช่วยลดข้อผิดพลาดของการส่งใบออเดอร์เปล่าเข้าครัว
